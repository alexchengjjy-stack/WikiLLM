# BreezySign 商業部門職務工作清單整理

> 本報告基於 2026 年 5 月最新業務週報與專案進展，針對好好簽（BreezySign）商業部門（Business Unit）的工作現狀進行全面梳理。以職務角色為維度，精確列出「待進行事項」、「可以優化調整」與「下一步工作建議」，旨在推動市場防禦、大戶收割與產品規格優化。

---

## 1. 業務銷售與客戶成功 (Sales & Customer Success)

當前核心現狀：**面臨點點簽（DottedSign）漲價客群移轉的黃金期**。福安管顧、太平洋旅行社、台中浸信會、麻吉行得通等多家大戶均因點點簽調漲價格而進行好好簽的評估與導入。

### 1) 待進行事項 (Immediate Tasks)
- [ ] **太平洋旅行社匯款與正式帳號開通**：該客戶已確定採購 40 人年費版（NT$60,000），正式版於 6 月 1 日起算。需協助於 5 月 31 日前開通 40 位體驗帳號，並在收到電匯後無縫轉為正式版。
- [ ] **福安管理顧問 API 串接與電訪報價跟進**：該客戶每年有 2 萬份簽署合約的高額用量，其點點簽合約於 6/30 到期。需提供 API 報價單，並預排一場 Google Meet 視訊教育訓練（因客戶期望錄製教育訓練給內部同事參考）。
- [ ] **台中浸信會「1年年約」報價追蹤**：經內部討論，此案每年約 1000 份文件，不適合提供 1 次訂閱 3 年的方案。需向客戶說明維持 1 年期年訂閱專業方案（牌價請款），並追蹤其行政執事會的審批提案進度。
- [ ] **聖美麗健檢體驗展期與批次簽跟進**：該客戶體驗版已協助展延至 6/21。其內部公告有 20 人簽署需求，CS 團隊已建議其使用「批次簽」方案代替 20 階簽署，需追蹤客戶的測試回饋與簽約意願。
- [ ] **奇恭 (GiGO) 連鎖遊樂場 6/30 到期採購跟進**：該客戶目前使用體驗版穩定（任務數已達 322），需提供商務 2 人版與企業 5 人版報價，引導其在 6/30 前完成匯款採購。
- [ ] **跟進即將到期之企業體驗版客戶**：
  - 人合國際（5/25 到期，已發 2 份任務，需提供使用手冊引導）。
  - 喜事來台灣分公司（5/25 到期，經銷商官網公開表單需求，需電訪關懷）。
  - 盈泰澤丞（5/27 到期，200~300份會員合約，關注聲明錄影簽試用回饋）。
  - 佶星廣告（5/27 到期，房屋現場簽約需求，跟進試用進展）。
  - 樸然子（5/29 到期，合約 30~50 份，觀察目前任務數為 0，需主動去電協助排障）。

### 2) 可以優化調整 (Optimizations)
- [ ] **優化電訪與聯絡資料品質**：當週留電話的 8 家中，仍有 4 家完全聯絡不到（涣潮、牧容、鼎倫、拉拉），應建立「註冊後 24 小時內黃金聯絡 SOP」，並針對聯絡不到者改採簡訊/Email 雙軌關懷。
- [ ] **建立退訂客戶挽回機制**：上月有 8 家客戶退訂（1專業、7企業），多數為「沒有回應」或「使用量不多」。應優化退訂流程中的原因調查，並在退訂後 15 天由 CS 進行「降轉免費版/低頻包」的主動挽留電訪。
- [ ] **小微客群分流引導**：針對如三亞旅行社（每月 3 份以內用量）等初期使用免費版即可滿足的客戶，應主動降轉並停止佔用高階客服與體驗版展期資源，讓 Sales 專注於高客單價企業戶。

### 3) 下一步工作建議 (Next Steps)
- [ ] **制定「點點簽大戶無縫轉移專案」銷售特惠**：針對被點點簽漲價波及的 20~100 人企業，Sales 團隊應主動設計「點點簽用戶跳槽好好簽特惠專案」，提供首年 8 折或免除前置設定費的優惠，截擊點點簽流失的客戶。

## 2. 行銷推廣 (Marketing)

當前核心現狀：**流量過度仰賴 Google 自然搜尋**。當週廣告、同事推薦與 AI 搜尋（ChatGPT 等）帶來的註冊量均為 0，推廣管道過於單一，且官方網站的公信力宣告處於「靜默狀態」。

### 1) 待進行事項 (Immediate Tasks)
- [ ] **正式站同步更新「能量登錄」E-E-A-T 宣告**：Staging 測試站首頁已完成數發部能量登錄與蒙恬科技上櫃背景（5211）的文字聲明部署，行銷團隊應協同工程團隊，儘速將此高信任度的宣告同步上線至正式站。
- [ ] **準備 2026/05 新版《電子簽章法》上路之 PR 公關稿**：配合新法實施，撰寫並發布新聞稿，強調「好好簽 100% 合規且通過數發部官方能量登錄」，提振品牌權威。

### 2) 可以優化調整 (Optimizations)
- [ ] **打破官網客戶案例（實績）零篇痛點**：好好簽在旅行社（富友、耐斯）、管顧、以及大型 SI 累積了豐富實績，但官網案例為 0 篇（點點簽有 15+ 篇）。應立即將「富友旅行社」的導入過程撰寫為首篇 Case Study，發布於官網 Blog。
- [ ] **啟動 AEO/GEO（生成式 AI 搜尋優化）佈局**：週報顯示 AI 搜尋轉化為 0。行銷團隊應在官網價格頁、首頁底部新增「電子簽章法合規常見問題 FAQ」語意板塊，方便 ChatGPT / Perplexity / Gemini 爬蟲精確抓取並推薦好好簽。

### 3) 下一步工作建議 (Next Steps)
- [ ] **同業口碑行銷與旅行業定向推廣**：鑑於太平洋、富友、耐斯、三亞等多家旅行社因「旅遊定型化契約」高頻簽署而群聚好好簽。行銷應包裝「旅行業線上定型化契約吃到飽」解決方案，在旅遊同業公會或社群進行定向廣告投放。

## 3. 產品經理與專案管理 (Product & Project Management)

當前核心現狀：**重大企業專案與 SaaS 功能規格重疊**。產品線需同時支援 Unify 範本管理者共享、公開表單附件下載及大戶高頻簽署限額防線等規格演進。

### 1) 待進行事項 (Immediate Tasks)
- [ ] **太平洋旅行社 Unify 範本共用設定變更**：該客戶要求由管理帳號統一分享範本給公司名下所有成員，且子帳號不允許自建範本。PM 需協調客服，於客服後台完成「UNIFY」客服端開關設定，並將此永久設定記錄於客戶資料庫中。
- [ ] **自我簽署 Bug 修復驗證**：聖美麗健檢等客戶反應的自我簽署問題已於 5/18 安排更版上線，需主動確認生產環境（Production）驗證結果是否 100% 正常。
- [ ] **整理台灣奇恭（GiGO）之 DocuSign 使用反饋**：將該客戶之前回饋的 DocuSign 優秀功能與使用痛點，整理並納入 SaaS 功能優化清單（Backlog），作為後續版本迭代的依據。

### 2) 可以優化調整 (Optimizations)
- [ ] **重構「Unify 範本共用權限」規格**：目前的範本 UNIFY 共用功能為「全開或全關」，且僅主帳號可分享，其他管理員無法分享。應將其優化為「角色權限分層設定」，允許「管理員角色」亦能進行範本分享，且「子帳號」在專屬共享夾之外仍保有自建私有範本之權限。
- [ ] **優化 Line 傳簽連結生成流程**：目前 Line 傳簽需先「填入發起人手機號碼」才能產生連結，流程繁瑣。產品應優化為「Line 傳簽一鍵生成連結並複製」之直覺按鈕，降低使用者操作門檻。

### 3) 下一步工作建議 (Next Steps)
- [ ] **落實「大戶定價防線」產品規格化**：針對福安、太平洋等高用量客戶，將「企業專業方案訂定每月簽署上限，超過則提供加購（每份 NT$15~30 元，每次加購 5 份）」的防超量機制，正式寫入 SaaS 標準產品定價規格書。
- [ ] **設計「大型公告非依序平行簽署」功能**：聖美麗健檢等公司有「1份公告文件需全體 20 位員工簽署」之需求。目前 5 階依序簽署不符實務，應設計「平行廣播簽署」功能，多人可同時簽名並最終合併於單一 PDF 中。

## 4. 技術工程 (Engineering)

當前核心現狀：**Staging 測試站準備就緒，正進行最後技術 SEO 的 DOM 重構**。同時面臨軟訊資訊、光曜町等客戶之 API 串接技術支援。

### 1) 待進行事項 (Immediate Tasks)
- [ ] **實施測試站首頁 DOM Heading 標籤調整**：根據診斷報告，將前半部 4 大大標題由 `<h3>` 改為 `<h2>`，其底下的子功能描述 `<h4>` 順延改為 `<h3>`。保持後半部 H2/H3 結構，以提振技術 SEO 評分至 88+ 分。
- [ ] **開通軟訊資訊與光曜町數位行銷之 API 測試帳號**：為上述客戶提供 API 整合測試環境，並發送好好簽 API 技術串接指南文件。

### 2) 可以優化調整 (Optimizations)
- [ ] **公開表單「附件（身分證等）額外下載」優化**：夢曦文化等客戶反應「公開表單中直播主上傳的身份證附件希望可以額外單獨下載原始檔，而非僅嵌在 PDF 中」。工程團隊應優化公開表單的後台附件下載機制，支援「一鍵打包下載原始高品質圖片」。

### 3) 下一步工作建議 (Next Steps)
- [ ] **同步測試站優化成果至正式環境**：當 DOM Heading 調整在 Staging 測試站驗證通過後，應協同行銷將「微格式 JSON-LD 價格結構化資料」與「E-E-A-T 能量登錄文字宣告」**正式同步發布至正式站（Production）**。
- [ ] **API 測試沙盒（Sandbox）自動化部署**：建立標準的 API 自動化測試沙盒，減少技術團隊手動開通用戶 API 測試的重複工時。

## 5. 營運、行政與法務 (Operations, Admin & Legal)

當前核心現狀：**配合 SaaS 續訂與大戶轉帳，處理多筆年租電匯報價單開立**。同時需因應新版電子簽章法完成合規宣告。

### 1) 待進行事項 (Immediate Tasks)
- [ ] **開立太平洋旅行社（40人, NT$60,000）電匯報價單**：提供正式電匯請款資料，確認匯款後通知 Sales/CS 團隊變更正式版起算日（6/1）。
- [ ] **開立台中浸信會（專業方案年費）報價單**：配合其执事會審批流程，出具正式年約請款文件。

### 2) 可以優化調整 (Optimizations)
- [ ] **引薦與合作廠商分潤管理優化**：當週有中華電信引薦（光曜町）、百加資通 BPM、統一數網等合作案。應優化合作轉介的分潤或拆帳結算機制，建立自動化的行政報表。
- [ ] **電子簽章安全與條款合規更新**：因應 2026/05 新版《電子簽章法》上路，行政與法務應審查並更新好好簽的「用戶服務協議」與「隱私權宣告」，確保與數發部能量登錄標準完美合規。

### 3) 下一步工作建議 (Next Steps)
- [ ] **多年期預收帳款會計處置標準化**：針對如台中浸信會「預算有限期望 1 次訂閱 3 年」之客戶。法務與財務應制定「多年期預付款認列合約」，在行政層面允許預收 3 年期費用並按年遞延認列營收，以利 Sales 團隊簽署長約。
